# API «Полезные материалы» — контракт от фронтенда

Документ описывает, какие эндпоинты и структуры данных фронтенд ожидает от бэкенда
для раздела **«Полезные материалы»** (`/resources`): статьи, тесты и опросы.

Статус: **предложение для обсуждения с командой бэкенда**.
Сейчас весь раздел работает на моках (см. [последний раздел](#что-сейчас-на-моках)),
после появления API моки удаляются, формат ответов должен совпадать с описанным ниже.

Swagger существующего API: https://api.psychohelp-mospoly.ru/docs

---

## Структура раздела на фронтенде

| Страница           | URL                                        | Что показывает                                    |
| ------------------ | ------------------------------------------ | ------------------------------------------------- |
| Полезные материалы | `/resources?entity=articles\|tests\|polls` | три вкладки со списками карточек                  |
| Статья             | `/article/:slug`                           | полный текст статьи                               |
| Прохождение теста  | `/test/:slug`                              | вопросы по одному, ответы вариантами              |
| Результат теста    | `/test/:slug/result`                       | текстовый результат + рекомендации                |
| Прохождение опроса | `/poll/:slug`                              | вопросы по одному + оценка и рекомендация в конце |

## Общие соглашения

1. **`slug`** — уникальный человекочитаемый идентификатор для URL:
   латиница в нижнем регистре, цифры, дефисы (`kakie-chuvstva-vy-podavlyaete`).
   Все детальные `GET` — по slug (по аналогии с уже существующим `/news/{slug}`).
2. **`id`** — внутренний идентификатор сущности (строка). `POST`-запросы идут по `id`.
3. **Даты** — ISO 8601 (`2025-10-11T00:00:00.000Z`). Форматирование («11.10.2025») делает фронт (dayjs).
4. **Количества — числами**, не строками: `questionsCount: 10`, `durationMinutes: 5`.
   Строки «10 вопросов», «5 минут» фронт собирает сам (важно для склонений).
5. **Картинки** — абсолютный URL либо путь относительно image-сервиса
   (как у существующих сущностей через `VITE_REACT_APP_IMAGE_URL`) — нужно зафиксировать один вариант.
   Поле `imageSrc` **во всех сущностях необязательное**: если бэк его не пришлёт, фронт
   подставит обложку-заглушку (статьи — `article-cover`, тесты/опросы и результат теста — `test-cover`).
6. **Доступ**: все `GET` публичные (раздел виден без авторизации).
   `POST`-ы тоже анонимные — в опросах пользователю обещано
   «все ответы анонимны и конфиденциальны».
7. **Ошибки**: `404` — неизвестный slug/id; `400` — невалидное тело запроса
   (формат ошибок — как в остальном API).
8. **Сортировка списков** — от новых к старым (для статей обязательно).
9. Пагинация в первой версии **не требуется**: фронт получает весь список и
   показывает первые 6 карточек с кнопкой «Показать ещё». Если материалов станет
   много, договоримся о `limit/offset` отдельно.
10. **Необязательные поля** (`imageSrc`, статистика опроса, описание и т.п.) можно
    как не присылать вовсе, так и присылать со значением `null` — фронт трактует
    `null` и отсутствие поля одинаково (поле просто не используется / показывается
    заглушка). То есть FastAPI-шный `Optional[...] = None` подходит как есть.

## 1. Статьи

### 1.1. `GET /articles` — список для вкладки «Статьи»

```json
[
  {
    "slug": "strah-neizvestnosti-posle-universiteta",
    "title": "Страх неизвестности или куда пойти после окончания университета?",
    "description": "Не секрет, что каждому из нас хочется определённости…",
    "imageSrc": "https://…/images/article-cover.jpg",
    "author": "Сафронова Ольга",
    "date": "2025-09-11T00:00:00.000Z"
  }
]
```

| Поле          | Тип          | Обяз. | Комментарий                      |
| ------------- | ------------ | ----- | -------------------------------- |
| `slug`        | string       | да    | уникальный, для URL              |
| `title`       | string       | да    | заголовок карточки               |
| `description` | string       | да    | анонс; фронт обрезает до 3 строк |
| `imageSrc`    | string       | нет   | обложка карточки                 |
| `author`      | string       | да    | автор                            |
| `date`        | string (ISO) | да    | дата публикации                  |

### 1.2. `GET /articles/{slug}` — полная статья

```json
{
  "slug": "kak-govorit-o-svoih-chuvstvah-chestno",
  "title": "Как научиться говорить о своих чувствах честно?",
  "author": "Иванов Иван",
  "date": "2025-10-11T00:00:00.000Z",
  "content": [
    { "type": "p", "data": "Честно ли вы говорите о своих чувствах?…" },
    { "type": "image", "src": "https://…/images/cover.png", "alt": "Описание картинки" },
    { "type": "h2", "data": "Понимание своих чувств" },
    {
      "type": "block",
      "data": [
        { "type": "p", "data": "Задайте себе вопросы:" },
        { "type": "ul", "items": ["Что я чувствую?", "Почему я так себя чувствую?"] }
      ]
    }
  ]
}
```

`content` — упорядоченный массив блоков. Поддерживаемые типы:

| `type`      | Поля                         | Что рендерится                                  |
| ----------- | ---------------------------- | ----------------------------------------------- |
| `p`         | `data: string`               | абзац                                           |
| `h1`…`h6`   | `data: string`               | заголовок соответствующего уровня               |
| `image`     | `src: string`, `alt: string` | картинка на всю ширину                          |
| `ul` / `ol` | `items: string[]`            | маркированный / нумерованный список             |
| `block`     | `data: (p \| ul \| ol)[]`    | визуально сгруппированный блок (абзац + список) |

Блоки других типов фронт молча игнорирует — добавление нового типа требует
правок на фронте, согласовываем заранее.

## 2. Тесты

Сценарий: список → прохождение (один вопрос на экран, один вариант ответа) →
отправка ответов → **бэк считает результат** → страница результата.

### 2.1. `GET /tests` — список для вкладки «Тесты»

```json
[
  {
    "id": "1",
    "slug": "kakie-chuvstva-vy-podavlyaete",
    "title": "Какие чувства вы подавляете?",
    "description": "Этот тест поможет понять, какие эмоции вы чаще всего скрываете…",
    "imageSrc": "https://…/images/test-cover.png",
    "questionsCount": 10,
    "durationMinutes": 5
  }
]
```

### 2.2. `GET /tests/{slug}` — тест с вопросами

```json
{
  "id": "1",
  "slug": "kakie-chuvstva-vy-podavlyaete",
  "title": "Какие чувства вы подавляете?",
  "questions": [
    {
      "id": "1",
      "title": "Часто ли вы испытываете тревогу без причины?",
      "options": [
        { "id": "yes", "label": "Да" },
        { "id": "no", "label": "Нет" },
        { "id": "unknown", "label": "Не знаю" }
      ]
    }
  ]
}
```

- `questions[].options[].id` — произвольная строка, фронт её **не интерпретирует**,
  только отправляет обратно. Баллы, веса и прочая логика — на бэке.
- Порядок вопросов и вариантов — как в ответе, фронт не перемешивает.

### 2.3. `POST /tests/{id}/result` — отправка ответов, получение результата

Запрос (ответы на **все** вопросы, по одному варианту на вопрос):

```json
{
  "answers": [
    { "questionId": "1", "optionId": "yes" },
    { "questionId": "2", "optionId": "rather-no" }
  ]
}
```

Ответ — готовый текстовый результат (подсчёт целиком на бэке):

```json
{
  "id": "2",
  "title": "Вы иногда откладываете свои чувства",
  "imageSrc": "https://…/images/result.jpg",
  "description": [
    "Вы умеете слышать себя, но в напряжённых ситуациях…",
    "Отложенные эмоции не исчезают…"
  ],
  "recommendations": [
    "Доверяйте интуиции и чувствам",
    "Ведите дневник эмоций хотя бы несколько минут в день"
  ]
}
```

| Поле              | Тип      | Комментарий                                                                          |
| ----------------- | -------- | ------------------------------------------------------------------------------------ |
| `id`              | string   | идентификатор варианта результата                                                    |
| `title`           | string   | название результата (сейчас не отображается, но нужен — alt картинки, планы дизайна) |
| `imageSrc`        | string   | иллюстрация результата                                                               |
| `description`     | string[] | абзацы текста результата                                                             |
| `recommendations` | string[] | пункты блока «Рекомендации»                                                          |

Валидация на бэке: все вопросы отвечены, `optionId` принадлежит вопросу — иначе `400`.

## 3. Опросы

Сценарий: список → прохождение (как у тестов) → **оценка опроса** (1–5 звёзд)
и вопрос «порекомендовали бы вы этот опрос другим?» (да/нет) → отправка одним
запросом → статичный экран «Спасибо за участие». Результат пользователю **не показывается**.

### 3.1. `GET /polls` — список для вкладки «Опросы»

Карточка опроса, в отличие от теста, содержит агрегированную статистику:

```json
[
  {
    "id": "1",
    "slug": "uroven-stressa-i-trevozhnosti",
    "title": "Уровень стресса и тревожности",
    "description": "Этот опрос направлен на изучение того, как люди справляются со стрессом…",
    "imageSrc": "https://…/images/poll-cover.jpg",
    "questionsCount": 10,
    "durationMinutes": 5,
    "stats": {
      "passedCount": 146,
      "recommendPercent": 86,
      "rating": 4.7
    }
  }
]
```

| Поле `stats`       | Тип                                    | Обяз. | Отображение                       |
| ------------------ | -------------------------------------- | ----- | --------------------------------- |
| `passedCount`      | number                                 | нет   | «146 прошли опрос»                |
| `recommendPercent` | number (0–100)                         | нет   | «86% рекомендуют»                 |
| `rating`           | number (1–5, одна цифра после запятой) | нет   | «4.7 рейтинг» + бейдж на картинке |

`stats` бэк агрегирует из присланного пользователями `feedback` (см. 3.3).
**Каждое поле `stats` необязательно** (как и сам объект `stats`): любой отсутствующий
показатель фронт просто не отображает, а без `rating` не показывается и бейдж на картинке.
Это закрывает случай, когда опрос ещё никто не прошёл — можно не присылать статистику вовсе.

### 3.2. `GET /polls/{slug}` — опрос с вопросами

Формат идентичен `GET /tests/{slug}` (вопросы с вариантами, `optionId` фронтом не интерпретируется).

### 3.3. `POST /polls/{id}/answers` — отправка ответов и обратной связи

```json
{
  "answers": [
    { "questionId": "1", "optionId": "often" },
    { "questionId": "2", "optionId": "sometimes" }
  ],
  "feedback": {
    "rating": 4,
    "recommend": true
  }
}
```

| Поле                 | Тип     | Валидация                                              |
| -------------------- | ------- | ------------------------------------------------------ |
| `answers`            | array   | все вопросы отвечены, `optionId` принадлежит вопросу   |
| `feedback.rating`    | integer | 1–5, обязательное (фронт не даёт отправить без оценки) |
| `feedback.recommend` | boolean | обязательное                                           |

Ответ: **`204 No Content`** — фронту ничего не нужно, он показывает статичный экран благодарности.

## Что сейчас на моках

После реализации API эти файлы заменяются запросами (React Query `queryOptions`
в `entities/`, по образцу therapist/news):

| Файл                                                            | Заменяется на                                    |
| --------------------------------------------------------------- | ------------------------------------------------ |
| `src/pages/resources-page/entities/articles/mocks.ts`           | `GET /articles`                                  |
| `src/pages/resources-page/entities/tests/mocks.ts`              | `GET /tests`                                     |
| `src/pages/resources-page/entities/polls/mocks.ts`              | `GET /polls`                                     |
| `src/pages/article-page/mocks.ts`                               | `GET /articles/{slug}`                           |
| `src/pages/test-page/mocks.ts`                                  | `GET /tests/{slug}`                              |
| `src/pages/test-result-page/mocks.ts` (включая подсчёт баллов!) | `POST /tests/{id}/result`                        |
| `src/pages/poll-page/mocks.ts`                                  | `GET /polls/{slug}` + `POST /polls/{id}/answers` |

Типы фронтенда, с которыми должен совпасть формат: `models.ts` рядом с каждым моком.

## Открытые вопросы к бэку

1. Картинки: абсолютные URL или пути под `VITE_REACT_APP_IMAGE_URL`?
2. `stats` опроса при нулевом числе прохождений — нули или поле отсутствует?
3. Нужна ли защита от повторных прохождений опроса (cookie/fingerprint/ничего)?
   Фронт сейчас никак не ограничивает.
4. Пагинация списков — закладывать сразу или после наполнения контентом?
5. Будут ли опросы/тесты со множественным выбором или свободным ответом?
   Сейчас фронт поддерживает только один вариант на вопрос.
